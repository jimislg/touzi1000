**为什么这是 P0**：取一家「生意组存疑 1 个、治理组无存疑」的公司——

**建议**
1. 先冻结并发写入：审计基线里 `SKILL.md`（11:10）与 `precheck.py`（11:10）被同一轮 auto backup 改过，而 JSON / lint / 模板没跟上，说明存在多写者。整改前先确认谁在改，避免边改边审。
2. 定**唯一权威**：以 `methodology-v3.4.json` 为机读权威，新增 `classification` 节点（三组定义、基准档、降档规则、仓位上限），SKILL.md 只引用不重写规则数值。

4. 加**四源对账脚本**：喂同一组输入，比对 `SKILL.md` 表格解析值、`methodology-v3.4.json`、`precheck.py --json` 输出、`investment-hq/data/methodology.json`，任一不一致即 FAIL。

**验收标准**：同一组「生意组存疑 1 / 治理组无存疑」输入，四源全部输出 B；任一文件单独回滚到旧口径，对账脚本必须 FAIL。`precheck.py class --claim A` 在该输入下必须报「应判 B」。

### 第 2 组（P0）唐朝法交付闸门是装饰性的

- `scripts/gate.py:100`：`checks.append(("倍数修复已披露", not need_sens or True, ...))` —— `or True` 使该项**恒为 PASS**，无论内含修复是否 >10%
- `scripts/gate.py:124–148`：`run_gate()` 里 `ok` 只由 `decomp_res["ok"]` 决定；`hurdle_res["checks"]` **只 print 不参与 ok 累计**。即「反解价自洽」「终值即现价已声明」等检查即使为 False，闸门照样 PASS
- `scripts/calc.py`：全文无 `import gate`、无 `run_gate`、无 `assert`；`:458–459` 直接写 `result.json`，`:771` 打印完成。`gate.py` 只在 `__main__ --demo` 下自测（`:173,182` 恒隆算例）
- 结论：**主流程从未调用闸门**，回测/案例生成不受任何 gate 约束

**建议**：`calc.py` 在写完结果前组装 `decomp_res` / `hurdle_res` 并调用 `run_gate()`，`if not ok: sys.exit(1)`；同时把 `or True` 改成真实条件（或明确降级为「仅提示，不进 checks」并改名，别挂在 PASS 列表里），`run_gate` 累计所有 checks。

**验收标准**：构造一个「反解价不自洽」的负例输入，整条 `calc.py` 流水线必须非零退出且**不覆盖** `result.json`；三个既有 case 重跑结果不变。
