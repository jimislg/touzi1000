# 投资平台优化建议与验收要求

> 日期：2026-10-10。依据：当次只读检查 investment-platform 的前端、配置读写服务、最新配置、v3.4方法论，以及《投资目标可行性与执行风险研究报告》。本文件是优化需求草案，不是已实施功能，不改变投资规则、云端数据或历史结论。

平台首先要回答四件事：我的真实资产是什么；当前机会具备什么证据；采取行动会怎样改变财富和股息路径；实际结果证明哪些假设对、哪些错。界面和功能围绕这四件事组织。

## 第一批：先修复会误导决策的问题

| 优先级 | 问题与现有证据 | 改动要求 | 验收标准 |
|---|---|---|---|
| P0 | 公司信息有多个副本：福耀持仓A、池内B；腾讯持仓标签与研究结论不同 | 公司质量、研究完成度、正式估值状态各有唯一来源；页面引用同一版本。自动回报标签仅来自合格模型，不用手工label替代 | 同一公司各页状态一致；历史标签仍可追溯；未定价不能显示已认证目标达成型 |
| P0 | 大多数持仓股票池未填researchStatus；预测快照曾将未过现金桥的腾讯写done | 将研究完成度与估值审计分开。done不等于审计通过；缺失状态为未知，不默认通过 | 未提供现金桥证据时，正式定价和正式新增资格不可成立，质量A/B可保留 |
| P0 | 四档插值加权被称为组合预期回报，并用于复利推演 | 现有计算保留为“档位诊断”，标覆盖率/原模型日期/研究口径；正式组合成果逐项计算现金流与期末价值 | 缺正式模型时，显示“正式组合预测未完成”；不将插值值当承保回报或账户XIRR |
| P0 | 驾驶舱年股息标题税后，目标100万，但现行方法论目标税前；现金利息混入 | 固定税前年普通股息100万目标；税后到手另列。股息、利息、回购、特别股息、卖出回款分别显示 | 现金利息增加不会提高普通股息目标完成度；回购与卖出本金不记股息 |
| P0 | 福耀TTM短暂含三次派息；源文本与数值可能不一致 | 四种股息口径分栏：过去12个月公司派息、账户实际到账、正常化预计、未来已公告待付。每笔带所属期、登记/除息/支付日、币种、来源、性质 | 时间窗口滚动引起的TTM变化，不误报为公司减息；预计不能直接复制TTM |
| P0 | buyDate统一6月30日，10月另有新增；A股税额当前多处固定乘0.9 | 买入、卖出、费用、结算汇率与分红用逐笔台账；当前资产和历史人民币投入分离；税率按渠道、批次及最终持有期处理 | 10月买入的股数不参与之前派息；今日汇率改变不会改写历史人民币投入；未知到账不填0 |
| P0 | totalCapital既用于当前市值又被保存为targetCapital；推演每次使用完整5/10年 | 分离固定起始本金、原始目标日、当前资产、外部累计净入金、剩余期限；新增钱和投资收益分别归因 | 改现价/刷新不改变原本金及目标日期；延期需要明确新版本；加钱不会被算成投资收益 |
| P0 | 计算器writeTier可直接写buyPrice并保存 | 分开手工关注价、情景价格、冻结正式H档和实际成交价。计算器输出留在情景草稿，须满足审计与第四步条件才能取得正式资格 | 计算器改EPS或PE只改变草稿；正式信号和估值版本保持不变 |

正式资格应分别验证：经济质量合格、估值审计通过、数据时效合格、价格达标、组合适配合格。某项缺失明确写原因。价格触及旧档位时可以提醒刷新研究，但不能显示为已获得正式新增资格。金融等行业使用方法论批准的适用现金/资本桥，不强套工业企业口径。

用户自主交易权保留。超出书面门槛的成交在实际台账中如实记入，同时附“用户主动例外”的依据、风险、时间和适用交易；不能事后修改估值参数或等级让它看起来符合原纪律。系统记录已有授权，不反复要求确认。

## 第二批：补齐真正影响投资决定的功能

### 1. 目标页：三条路径并排

- 目标要求线：依据固定目标日期和当前资产反推剩余年化。
- 规划情景线：用户选择的6%/8%/10%/12%等假设，明确“情景”而非预测。
- 有证据的组合线：正式个股模型汇总；未覆盖资产和模型缺口可见，缺模型不强行补默认收益。

设置每年或每月外部净投入、生活支取、股息复投比例、部署速度及现金收益；输出五年/十年财富、缺口、所需追加本金、延后期限与股息安全线。原目标不自动顺延，不通过上调增长“修复”落后。

验收例：起点1000万元、年化10%、十年零追加零支取、总回报已含股息，终值约2593.74万元。不能再加股息。每年末新增50万元，终值约3390.61万元；外部新增累计500万元与投资收益必须分列。

概率加权结果先加权期末财富再反推等效CAGR；权重明确是判断，不输出未经校准的达标概率。实际账户XIRR按完整日期现金流计算：股息留在账户属于内部现金流，不重复当外部入金；账户外支取才记投资者分配。资料缺失时禁止生成看似精确的实际业绩。

### 2. 现金页：解释等待的条件

区分实际现金、尚未到账计划投入、家庭必要储备、已承诺交易资金和可部署现金。现有现金与可投资资金如果相同，只能计一次。

展示不同部署时点下的期末财富，以及“等一年必须买到多高额外回报才补回时间损失”。注明部署后收益假设；不把现金拖累解释成强制满仓命令。将持仓、观察池、低风险资产按同币种、同期限、税费后口径比较，不能拿未达到审计和价格门槛的茅台等公司当可立即替代选项。

### 3. 公司页：一张可追溯决策卡

第一屏只保留：如何赚钱、最强优势、最大反证、研究状态与缺口、当前价及时间、正式估值或无法定价、三个经营验证指标、最近变化和下一步动作。

展开后可查财务桥、资本分配表、正常化与预测EPS、三情景、分红/回购/稀释、终值占比、来源及报告。假设与事实分开，财报期间、币种、分部与合并范围写清。

研究队列按照“影响现有资本最多、最接近可执行机会、最可能改变结论”排序。缺资料只进入补研究，不等同于公司经济质量差。证据未齐，不用小数位营造确定性。

### 4. 拟交易页：显示边际成果

输入拟成交价、资金来源及数量，比较继续持有、买入/换仓、保留现金。列出税费、币种、股息损失、悲观损失、相关风险、纳入前后五年/十年财富和股息安全覆盖。

净新增持仓变化与总资产变化区分；不得通过个股IRR简单加权替代组合成果。按现行规则检查价格、累计分档比例、已有持仓、总资产仓位和行业风险。不新增“所有新仓必须提高简单加权回报”的硬规则，允许有证据的风险分散价值。

### 5. 股息页：现金生活能力验收

展示普通股息税前、税后实际到账、正常化预计、特别股息、现金利息及公司分红来源集中度。给出正常状态与逐公司减息压力后的覆盖率；统一减息20%只是附加敏感性，不当作经验证的尾部风险分布。

增长阶段和支用阶段分别计算。支用后不能继续假设全部股息复投；如果保留20%用于增长，其余80%才是可支用收入。购买力以可调通胀情景披露，不静默修改税前名义100万元目标。

### 6. 复盘页：预测与事实对账

冻结每次研究的增长、利润率、资本投入、净股数、分红和终值假设。新财报更新实际值，并按增长错、利润率错、资本投入漏、股数判断错归因。股价短期涨跌单列，不代替经营验证。

规则变化记录原规则、新规则、证据及影响；不能用最近一次买入是否赚钱决定修改SOP。严重经营反证、分红政策变化、未完成重大并购更新和超限，触发审视，不机械触发清仓。

## 第三批：数据保存与工程保障

现有本地镜像、2秒自动保存、备份及云端同步机制保留。核心风险是：保存请求提交全部可编辑字段但没有版本校验；旧设备可能覆盖另一设备较新的字段。GET /api/config在cloudDirty时还会触发补传，这使研究读取不一定完全没有写入副作用。这是代码路径风险，本次未复现或宣称已经发生数据丢失。

必须补齐：

1. 版本号与冲突检测：保存携带读取版本，仅提交实际改动字段；过期版本显示差异，不静默覆盖。并发成交幂等处理，同一交易ID不能扣两次现金。
2. 可靠保存状态：区分本地已保存、云端已确认、等待同步、同步冲突。保存过程中用户又编辑时，旧请求返回不能把新改动标为已保存。客户端缓存带版本和时间，不仅凭字段为0就自动恢复旧值；零股数、零分红可能是正确状态。
3. 只读研究入口：AI和查看模式读取快照、来源与版本，不触发云端补传或浏览器自动补存。恢复同步由明确的写入机制负责。
4. 完整校验：股数与金额范围、证券代码和柜台、币种、日期、关联交易ID、合理字段类型；缺失不能默认为0，取数失败不能当作经营恶化或无分红。
5. 变更审计与可恢复备份：记录谁在何时改变什么、旧新值、原因和引用版本；备份带时间，恢复前能预览差异。研究计算、行情缓存与实际资产台账分开管理。
6. 凭据与业务配置分离：浏览器不获取访问口令原值，导出和报告不携带凭据。代码沿用GitHub项目约定，研究与需求归档codex-产出；历史原件保留。

这些要求可以渐进加入现有应用，不要求先更换框架或重写整个平台。需要抽出可以独立复核的计算模块，避免相同税率/现金/收益公式在不同页面各写一份并产生差异。

## 最小验收清单

| 测试场景 | 必须出现的结果 |
|---|---|
| 正常化现金桥未过，但手工填出高回报 | 仍无正式定价；情景计算可用，但不能获得正式新增资格 |
| 修改计算器EPS/退出PE | 不覆盖冻结档位和正式触发价 |
| 未填researchStatus/审计状态 | 显示未知及缺口，不默认done/pass |
| 同一公司在持仓页和池内 | 相同证券版本下状态一致 |
| 新增入金100万元 | 资产增加；目标日不变；不算100万元投资利润 |
| 行情跌10% | 当前资产和剩余要求更新；起始本金及历史结算成本不变 |
| 今日港币汇率变动 | 当前市值及人民币风险变化；历史结算成本不变 |
| 10月买入腾讯新股数 | 不计入此前已派股息的实际到账 |
| 福耀三笔TTM中的旧一笔滚出 | TTM正常滚动；正常化预计不自动按同幅度削减；不发虚假经营减息告警 |
| 分红来源接口失败 | 显示缺失/旧值日期，不能写0并自动覆盖 |
| 现金利息、回购、特别股息增加 | 不提高普通股息目标完成度 |
| 两台设备同时编辑不同持仓 | 新数据保留，冲突可见；不会以旧完整patch覆盖 |
| 同一成交重复导入 | 只影响一次持仓与现金 |
| 保存过程中又编辑 | 待保存的新改动仍可见且继续保存 |
| 只读研究打开 | 云端业务版本不因读取改变 |
| 财报导致正式价格变动超过10% | 旧价格线冻结，显示变化归因、证据与版本 |
| 全账户收益已经包含分红 | 终值不重复加股息；内部复投不算外部入金 |

执行顺序：先完成P0口径与资格控制；随后完善逐笔台账、目标与现金流引擎；再交付公司决策卡、交易比较和复盘。版本及同步冲突保障与P0同步推进。先不扩展自动交易、短线技术指标或高频新闻评分。
