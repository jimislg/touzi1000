## 已执行的改进

| 问题 | 原行为与风险 | 本轮结果 |
|---|---|---|
| 分红失败被当成零 | 上游超时、异常结构或金额缺失可落入 `dps:0`，网页将可信正值清零 | HTTP 和结构检查；失败返回 `dps:null`，网页保留旧值并标陈旧；历史错误缓存也不清零；手工DPS优先 |
| 零分红文案越界 | “近12个月无记录”被显示成“已确认停派” | 有效空列表仍可得零值，但只标“近12个月未分红”，不代替公司停派公告；未来除息不计入已实施 |
| 浏览器旧镜像复活零值 | `!(value>0)` 把清仓、零成本和零股息当成丢失字段，并自动补存旧值 | 仅在字段为 `null/undefined` 时补缺，保留服务端明确的零 |
| 无效股票行情被替代 | 股票现价为零时会继续找其他小于10的字段，可能把昨收当现价 | 特殊字段回退限定为 `whHKDCNY`；股票缺失现价保持无效，拒绝非法数字后缀 |
| 部分行情冒充完整实时 | 收到一条有效行情即可覆盖完整旧集合，影响市值与信号 | 网页API、小程序及快照构建核查全部请求代码；不完整时保留旧数据，不更新成功时间；网页再做客户端校验 |
| 仓位空间差100倍 | 网页漏除100；例如1000万本金、17%仓位、20%上限显示3000万空间，小程序为30万 | 两端共同调用 `positionRoom`，均显示30万 |
| 下一档误报 | 未到最深档时也可能提示“已到最深档”，未触发时最近档为空 | 两端共用 `ladderState`，正确展示最近档、下一档与最深档边界 |
| 小程序接近名单遗漏 | 总数包括仓位接近与价格接近，名称函数只接收第一个优先级 | 同时显示两类名称，与计数一致 |
| 云配置读取任意首行 | 小程序 `limit(1)` 未指定配置键，未来多行时可能读错 | 增加 `key=config` 条件，与网页版存储层一致 |
| 旧测试脚本可覆盖正式配置 | `test-cloud-roundtrip.js` 向正式 `app_config/config` 写入只有探针的对象 | 默认拒绝执行，只允许 `LG_MOCK_CLOUD=1`；内存读写、回读、恢复，不落云不落盘 |

新增 `investment-platform/public/investment-core.js` 为本轮共用函数的唯一源码。服务端直接 require、网页加载静态脚本；小程序使用构建副本 `utils/investment-core.js`，由 `scripts/sync-core.js` 同步。`verify.js` 逐字节检查两端副本，防止口径单边漂移。并未声称本轮已经完成所有旧计算函数的模块化。
